1. Product North Star

Core product sentence

Zoe Fashion is a social fashion ranking and comparison app where users can browse clothing, shoes, bags, accessories, and drops from many brands in one place, compare items side by side, and see what people with taste are ranking right now.

Core trigger

The app should be opened whenever a user wants to browse clothes, dress better, check new drops, compare options, save pieces, or make a purchase decision.

Behavior to create

Users should feel: “When I want to look better or buy something, I open Zoe first.”

What Zoe is

  • A universal fashion discovery layer.
  • A side-by-side comparison tool.
  • A ranked wishlist and taste profile.
  • A feed of fashion drops, restocks, alternatives, and ranking updates.
  • A social proof layer before purchasing.

What Zoe is not

  • Not a full marketplace at launch.
  • Not a cluttered shopping search engine.
  • Not a closet-upload app first.
  • Not a discount/deal app.
  • Not a complicated analytics dashboard.

2. Positioning and Product Promise

Positioning

A minimal social fashion app for discovering and comparing the best pieces across the internet.

Zoe should combine:

  • Lyst-style breadth: many brands and retailers in one place.
  • Instagram-style browsing: visual, fast, addictive, phone-native.
  • RedNote-style utility: useful discovery and searchable answers.
  • Beli-style ranking: personal and community rankings as the core differentiator.

3. Unified Fashion Catalog

Main product requirement

Zoe needs a unified product catalog that aggregates fashion items from many brand and retailer sources so users can browse everything in one place.

This catalog should include:

Clothing Shoes Bags Accessories Jewelry Watches Activewear Streetwear Designer Affordable basics Resale listings later

Catalog goals

1. One place to browse

Users should not need to open ten brand websites. Zoe should normalize products into one clean browsing experience.

2. Easy comparison

Users should compare similar items by price, material, fit, quality signal, popularity, ranking, availability, and style.

3. Ranking layer

Every product should be rankable into personal lists, community lists, creator lists, and alternative lists.

4. Decision layer

Zoe should help users decide whether something is worth buying, not just display product inventory.

Source priority

  1. Official brand or retailer APIs where available.
  2. Affiliate network product feeds such as product catalog APIs, CSV, XML, or JSON feeds.
  3. Retailer product feed partnerships for new arrivals, price, image, size, availability, and URL.
  4. Public product pages only where permitted by terms of service and robots.txt. Do not design the product around unauthorized scraping.
  5. Manual/editorial seed catalog for MVP if APIs are not ready.
Compliance rule: Use official APIs, affiliate feeds, partner feeds, or permitted public catalog access. Avoid unauthorized scraping. The coding agent should implement source adapters so ingestion methods can vary by brand while the app sees one normalized catalog.

5. Mobile Navigation

Five-tab bottom navigation

The app should be phone-first, simple, and thumb-friendly. Use five fixed tabs:

  1. Home — personalized browse feed.
  2. Search — search and explore all catalog items, brands, lists, and creators.
  3. Compare — side-by-side comparison tray and saved comparisons.
  4. Rank — ranking updates from friends, creators, brands, and community lists.
  5. Profile — user’s style identity, lists, wishlist, saves, and settings.
Change from original Zoe: This version should include a dedicated Compare tab because side-by-side item comparison is central to fashion purchase decisions. Rank Updates can still exist as the Rank tab.

7. Side-by-Side Compare System

Why compare is core

Fashion purchase decisions are often comparative. Users do not only ask “is this good?” They ask “is this better than that?” Zoe should make comparison effortless.

Compare flow

1. User taps Compare on any item card.
2. Item enters floating Compare Tray.
3. User adds 2-4 items.
4. User opens Compare page.
5. Zoe shows normalized side-by-side fields.
6. User can save comparison, ask friends, rank winner, or buy.

8. Ranking System

Ranking is the moat

The catalog makes Zoe useful. Ranking makes Zoe different. Every product should become part of a living taste graph.

Ranking types

Personal rankings

My best basics, my bag wishlist, shoes I actually wear, items I regret buying.

Community rankings

Best Uniqlo pieces, best work totes, best fall jackets, best sneakers under $150.

Creator rankings

Public ranked lists from style creators, campus tastemakers, menswear curators, and resale experts.

Alternative rankings

Best alternatives to specific designer items or viral fashion pieces.

Add-to-ranking flow

Tap Rank
  → Choose list or create new list
  → Place item manually or compare against existing entries
  → Add short note: “best fit for the price”
  → Choose visibility: public / followers / private
  → Publish ranking update or save silently

Ranking signals

  • Number of times ranked
  • Average rank position
  • Rank movement over time
  • Saves and wishlist adds
  • Creator authority weight
  • User similarity weight
  • Recency of rankings
  • Fit/quality complaints or praise

10. Minimal UI Rules

Design principle

The UI must be simple, clean, and addictive. It should feel like a tasteful social app, not a database, marketplace, or spreadsheet.

Non-negotiable UI rules

  1. One primary action per surface. Do not overwhelm users with too many buttons.
  2. Every product card has three tiny actions only: Save, Compare, Rank.
  3. Do not show too many technical fields on cards. Put detailed data inside item detail or compare page.
  4. Use large images and clean typography. Fashion is visual.
  5. Use warm neutral backgrounds. Avoid harsh shopping-app white and loud sale colors.
  6. Rank movement should be elegant. Use small arrows, numbers, and subtle color.
  7. Comparison should be visually clear. Side-by-side columns, no clutter.
  8. Search should be extremely prominent. Users need to find anything fast.

12. API + Ingestion Requirements

Primary requirement

The app should be designed to ingest product data from many brands, retailers, and servers through adapters. The front end should never care where the product came from. It should only consume the normalized Zoe catalog API.

Adapter interface

interface ProductSourceAdapter {
  sourceName: string;
  fetchProducts(cursor?: string): Promise<RawProductBatch>;
  fetchProductById(externalId: string): Promise<RawProduct>;
  normalize(rawProduct: RawProduct): CanonicalProductDraft;
  fetchAvailability?(externalId: string): Promise<AvailabilitySnapshot>;
  fetchPrice?(externalId: string): Promise<PriceSnapshot>;
}

Catalog API endpoints

Deduplication strategy

  • Exact match by brand + SKU if available.
  • Fuzzy match by brand + cleaned product name + color + image similarity.
  • Variant matching for color and size.
  • Manual admin override for important products.

13. MVP Scope

MVP must-have

  1. Auth and onboarding
  2. Style, brand, budget, and size preferences
  3. Unified product catalog
  4. Product search
  5. Home feed
  6. Item detail page
  7. Save / wishlist
  8. Compare tray and compare page
  9. Personal ranked lists
  10. Rank updates feed
  11. Creator/user profiles
  12. Basic brand pages
  13. Basic notifications

MVP can fake or seed

  1. Start with 10-30 brands manually seeded if live APIs are not ready.
  2. Use static product JSON to build frontend first.
  3. Use mock ranking scores until enough users rank items.
  4. Use editorial “best alternatives” lists before algorithmic matching.
  5. Use simple keyword search before vector search.

Recommended MVP brand/category focus

Phase plan

  1. Phase 1: Build frontend with seeded catalog JSON, Home, Search, Item Detail, Save, Compare, Ranking.
  2. Phase 2: Add backend catalog service and source adapter pattern.
  3. Phase 3: Add live brand/retailer/affiliate feeds and scheduled ingestion.
  4. Phase 4: Add personalized feed, ranking updates, restock/price alerts.
  5. Phase 5: Add creator monetization, affiliate links, and brand campaign tools.

14. Coding Agent Instructions

Build goal

Create a mobile-first app prototype for Zoe Fashion that demonstrates unified product browsing, side-by-side comparison, ranking, wishlist, and a minimal addictive feed.

Frontend implementation guidance

  • Use a mobile-first layout with a fixed bottom tab bar: Home, Search, Compare, Rank, Profile.
  • Keep UI minimal. Large product images, short text, soft neutral colors.
  • Every product card should expose Save, Compare, and Rank.
  • Use mock data first if real APIs are not available.
  • Implement a Compare Tray that persists selected items across screens.
  • Implement an Item Detail page with offers, alternatives, rankings, fit notes, and comparison actions.
  • Implement ranking lists and rank movement events.

Backend implementation guidance

  • Create a normalized product catalog API.
  • Create source adapters for brand or retailer feeds.
  • Store raw source responses separately from normalized products.
  • Implement deduplication by SKU first, fuzzy matching second.
  • Implement search over product name, brand, category, tags, and ranking lists.
  • Implement wishlist and compare groups as user-owned entities.
  • Implement ranking events for Rank tab feed.
